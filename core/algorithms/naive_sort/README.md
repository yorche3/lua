# Naive Sort — Lua

Implementación de la especificación [05_Naive_Sort](https://yorche3.github.io/programming_languages/core/algorithms/05_Naive_Sort/) en **Lua (5.3+)**, con **LuaRocks** como gestor de paquetes y **Busted** como framework de pruebas unitarias.

Tres algoritmos de ordenación con coste $O(n^2)$: **selection sort**, **bubble sort** e **insertion sort**, todos ordenando de forma ascendente el array recibido, sin bibliotecas de ordenamiento ni estructuras auxiliares.

### `src/naive_sort.lua` — Implementación

**ES:** Las tres funciones aceptan un array (o `nil`) y devuelven el array ordenado (o `nil`). Reciben el array y lo ordenan *in-place*.

**EN:** All three functions take an array (or `nil`) and return the sorted array (or `nil`). They receive the array and sort it *in-place*.

```lua
local naive_sort = {}

function naive_sort.selection_sort(arr)
    if arr == nil then return nil end
    local n = #arr
    if n <= 1 then return arr end
    for i = 1, n - 1 do
        local min_index = i
        for j = i + 1, n do
            if arr[j] < arr[min_index] then
                min_index = j
            end
        end
        if min_index ~= i then
            arr[i], arr[min_index] = arr[min_index], arr[i]
        end
    end
    return arr
end
```

## 📝 Notas de implementación / Implementation Notes

### 🧬 Ordenamiento *in-place* / In-place sorting

**ES:** En Lua las tablas son mutables y se pasan por referencia, así que las tres funciones reordenan la tabla recibida y devuelven esa misma tabla. Los tests aíslan cada caso copiando la entrada con un helper local `copyArray`, de modo que un caso no contamine los siguientes.

**EN:** In Lua tables are mutable and passed by reference, so all three functions reorder the received table and return that same table. The tests isolate each case by copying the input with a local `copyArray` helper, so one case cannot contaminate the next.

### 🆗 Indicador de fallo con `nil` / Failure indicator via `nil`

**ES:** La especificación exige un indicador de fallo y prohíbe lanzar excepciones. En Lua `nil` es el valor de «ausencia de valor», por lo que `if arr == nil then return nil end` es la comprobación idiomática y no requiere mecanismos artificiales. El caso `nil` se prueba de forma independiente del caso vacío (`{}`).

**EN:** The specification requires a failure indicator and forbids throwing exceptions. In Lua `nil` is the "absence of value", so `if arr == nil then return nil end` is the idiomatic check and needs no artificial mechanism. The `nil` case is tested independently from the empty case (`{}`).

### 🔢 Indexación basada en 1 / 1-based indexing

**ES:** Lua indexa las tablas desde 1, así que las cotas del pseudocódigo se desplazan una posición: `for i = 0 to n - 2` pasa a `for i = 1, n - 1`, `for j = i + 1 to n - 1` pasa a `for j = i + 1, n` y la inserción recorre `for i = 2, n` con `while j >= 1`. El número de iteraciones y el orden de las comparaciones son idénticos a los del pseudocódigo.

**EN:** Lua indexes tables from 1, so the pseudocode's bounds shift by one: `for i = 0 to n - 2` becomes `for i = 1, n - 1`, `for j = i + 1 to n - 1` becomes `for j = i + 1, n` and insertion walks `for i = 2, n` with `while j >= 1`. The iteration count and the order of comparisons are identical to the pseudocode's.

### 🔁 La bandera `swapped` con `break` / The `swapped` flag with `break`

**ES:** `bubble_sort` mantiene la bandera `swapped` que exige la especificación: si una pasada completa no realiza ningún intercambio, el array ya está ordenado y el bucle se corta con `if not swapped then break end`. Es lo que convierte el mejor caso en $O(n)$.

**EN:** `bubble_sort` keeps the `swapped` flag required by the specification: if a full pass performs no swap, the array is already sorted and the loop is cut with `if not swapped then break end`. This is what makes the best case $O(n)$.

### ➿ Cotas de los bucles / Loop bounds

**ES:** La pasada interna de bubble usa `for j = 1, n - i`, equivalente al `0 to n - 2 - i` del pseudocódigo una vez aplicado el desplazamiento de la indexación basada en 1. El rango de Lua ya incluye ambos extremos, así que no hay desplazamientos manuales que justificar.

**EN:** Bubble's inner pass uses `for j = 1, n - i`, equivalent to the pseudocode's `0 to n - 2 - i` once the 1-based shift is applied. Lua's range includes both ends, so there are no manual offsets to justify.

### 🔀 Estabilidad de `insertion_sort` / `insertion_sort` stability

**ES:** El bucle interno se detiene con la comparación estricta `arr[j] > key`; los elementos iguales no se desplazan, por lo que `insertion_sort` es estable. El caso 1 (`{5, 2, 9, 1, 5, 6}`, con dos cincos) se beneficia de ello, aunque la comparación de los tests se hace sobre valores y no sobre identidad.

**EN:** The inner loop stops on the strict comparison `arr[j] > key`; equal elements do not shift, so `insertion_sort` is stable. Case 1 (`{5, 2, 9, 1, 5, 6}`, with two fives) benefits from it, although the tests compare values rather than identity.

### 🏷️ Naming y visibilidad / Naming and visibility

**ES:** Las funciones usan `snake_case` (`selection_sort`), que es a la vez la convención de Lua y el nombre que emplea la especificación, así que la API coincide con el contrato sin traducciones. El módulo es una tabla local que se devuelve con `return naive_sort`; no hay `main()`: el punto de entrada es el propio runner de Busted.

**EN:** Functions use `snake_case` (`selection_sort`), which is both Lua's convention and the name used by the specification, so the API matches the contract with no translation. The module is a local table returned with `return naive_sort`; there is no `main()`: the entry point is Busted's own runner.

### 🧪 Estructura de los tests / Test structure

**ES:** Una única suite con 3 tests. Dos detalles importantes: (1) la comparación usa `assert.same` porque en Lua `==` sobre tablas compara referencias, no contenidos; (2) el mensaje del contrato (`"{algorithm} should sort an unsorted array"`) se pasa como tercer argumento de la aserción, que luassert usa como mensaje de fallo y antepone a la salida, permitiendo identificar el algoritmo y el caso.

**EN:** A single suite with 3 tests. Two important details: (1) the comparison uses `assert.same` because in Lua `==` on tables compares references, not contents; (2) the contract message (`"{algorithm} should sort an unsorted array"`) is passed as the assertion's third argument, which luassert uses as the failure message and prefixes to the output, making it possible to identify the algorithm and the failing case.

```lua
describe("naive_sort", function()
    it("selection_sort", function()
        assertSortsAllCases(naive_sort.selection_sort, "selection_sort")
    end)

    it("bubble_sort", function()
        assertSortsAllCases(naive_sort.bubble_sort, "bubble_sort")
    end)

    it("insertion_sort", function()
        assertSortsAllCases(naive_sort.insertion_sort, "insertion_sort")
    end)
end)
```
